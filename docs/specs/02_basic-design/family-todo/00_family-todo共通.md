# 家族 de TODO！ 基本設計 — 共通仕様

## 用語

| 用語 | 意味 |
| --- | --- |
| 家族グループ | ToDoを共有する単位。1ユーザーは常に1グループにのみ所属する（MVP） |
| 登録ユーザー | Googleログインで参加するメンバー |
| 非登録メンバー | 名前のみ登録される担当者（例: 子供）。自分でログインしない |
| フォロー役 | 非登録メンバーを担当者に含める場合に必須の登録ユーザー。当該ToDoの通知はフォロー役に届く |

## 権限

- グループ内の操作権限は全メンバー一律（ToDo作成・編集・削除、コメント編集・削除、招待リンク発行など）。
- 例外: 家族グループそのものの削除は、グループの作成者のみ実行できる。
- 1ユーザーは常に1つの家族グループにのみ所属する（MVP。複数グループ対応は将来拡張）。

## 認証・アクセス制御

- 認証はGoogleログイン（OAuth）のみ。セッションはhttpOnly Cookie + D1の`sessions`テーブルで管理する（詳細 → [`30_ログインセッション管理.md`](../../03_detail-design/family-todo/30_ログインセッション管理.md)）。
- 未認証でのAPIアクセスは `401`。
- グループに未所属のユーザーが、ToDo・コメント等グループ内リソースのAPIを呼んだ場合は `403`。
- 家族グループ削除APIを作成者以外が呼んだ場合は `403`。

## API共通規約

- ベースパス: `/api/v1`（実装確認の結果、変更があれば本書を更新する）。
- リクエスト/レスポンスはJSON。
- 日時は ISO 8601（UTC）。
- 共通エラーレスポンス: `{ "error": { "code": "string", "message": "string" } }`
- 主なHTTPステータス: `200`/`201`/`204`（成功）、`400`（入力エラー）、`401`（未認証）、`403`（権限エラー）、`404`（対象が存在しない）、`409`（競合。例: 非登録メンバー名の重複）。

## 共通のUI・データ方針

- モバイルファーストで設計する（詳細は `DESIGN.md` 参照）。
- 削除は物理削除（ToDoの削除、グループの削除）。削除前に確認ダイアログ（`AlertDialog`）を表示する。
- カテゴリ（学校・仕事・習い事・家事・買い物・その他）は固定マスタ。グループに依存しない全体共通データで、MVPでは編集不可。
