# 個人設定画面

共通仕様（用語・権限・API共通規約）は [`00_family-todo共通.md`](00_family-todo共通.md) を参照。

## 1. 画面の目的

自分自身に関する設定を変更する。アプリ内での表示名、通知の種類ごとのON/OFF、期限接近リマインドを送るタイミング、時刻を指定していない期限をいつとして扱うかを、この画面で設定する。

ここでの設定は自分にだけ効く。家族の他のメンバーの通知には影響しない。

## 2. 画面へのアクセス条件・初期表示

- ログイン済みのユーザーが対象。家族グループへの所属は問わない。
- ToDo一覧画面のヘッダーメニューから開く。
- 画面表示時に `GET /users/me` と `GET /notification-settings` を呼び、現在の値を各項目に入れておく。
- 各項目は変更するたびに個別に保存する（画面全体の「保存」ボタンは設けない。設定項目が独立していて、まとめて保存する必要が無いため）。

## 3. 表示項目

### 3.1 プロフィール

| 項目 | 入力方法 | 備考 |
| --- | --- | --- |
| 表示名 | 1行の入力欄と「保存」ボタン | 家族グループ内のメンバー一覧・担当者・コメントに出る名前。初期値はGoogleアカウントの氏名 |
| メールアドレス | 表示のみ | Googleアカウントのメールアドレス。変更できない |

### 3.2 通知

| 項目 | 入力方法 | 説明文 |
| --- | --- | --- |
| ToDoが追加されたとき | ON/OFFのスイッチ | `家族の誰かがToDoを追加したときに知らせます。` |
| 自分が担当者になったとき | ON/OFFのスイッチ | `あなたが担当者に設定されたときに知らせます。ログインしないメンバーの通知の受け取り役になっている場合も含みます。` |
| 期限が近づいたとき | ON/OFFのスイッチ＋タイミングの選択 | `期限の前に知らせます。` |
| 期限を過ぎたとき | ON/OFFのスイッチ | `期限を過ぎても未完了のToDoを知らせます。` |

- 「期限が近づいたとき」のタイミングは、次の7つから1つ選ぶ。既定は「1日前」。

| 表示 | `remind_before_value` | `remind_before_unit` |
| --- | --- | --- |
| 1時間前 | 1 | `hours` |
| 3時間前 | 3 | `hours` |
| 6時間前 | 6 | `hours` |
| 1日前 | 1 | `days` |
| 2日前 | 2 | `days` |
| 3日前 | 3 | `days` |
| 1週間前 | 7 | `days` |

- 「期限が近づいたとき」がOFFのときは、タイミングの選択欄を操作不可にする（値は保持したままにする）。

### 3.3 期限の扱い

| 項目 | 入力方法 | 説明文 |
| --- | --- | --- |
| 時刻を決めていない期限の基準時刻 | 選択（0:00〜23:00の1時間ごと） | `時刻を指定していない期限は、この時刻を締め切りとして通知します。` 既定は `20:00` |

- 「9/3」のように日付だけを指定したToDoは、この設定の時刻を期限とみなす。既定の `20:00` なら、期限は「9/3 20:00」として扱う。
- 期限接近の通知も期限超過の判定も、この時刻を基準に行う。例: 基準時刻 `20:00`・リマインド「1日前」なら、9/3が期限のToDoの通知は 9/2 20:00 に届く。
- 時刻まで指定してあるToDoにはこの設定は影響しない。

### 3.4 Push通知の受け取り状態

| 状況 | 表示 |
| --- | --- |
| ブラウザで通知が許可されている | `この端末では通知を受け取れます。` |
| まだ許可も拒否もしていない | `この端末では通知を受け取れません。` ＋「通知を許可する」ボタン（押すとブラウザの許可リクエストを表示する） |
| ブラウザで拒否されている | `この端末では通知がブロックされています。ブラウザの設定から通知を許可してください。` |
| iOSでホーム画面に未インストール | `iPhone・iPadでは、ホーム画面に追加すると通知を受け取れます。` ＋「追加のしかたを見る」ボタン（[`24_iOSインストール案内.md`](24_iOSインストール案内.md) を開く） |

- ここでの表示は端末・ブラウザごとの状態であり、3.2の通知ON/OFF（アカウント単位の設定）とは別のものとして分けて表示する。

### 3.5 その他

| 項目 | 内容 |
| --- | --- |
| 「ログアウト」ボタン | 押すと確認ダイアログを表示する |

## 4. 入力チェック

| 項目 | チェック内容 | エラー文言 |
| --- | --- | --- |
| 表示名 | 未入力（空白のみも含む）でないこと | `表示名を入力してください。` |
| 表示名 | 20文字以内 | `表示名は20文字以内で入力してください。` |

- 通知のスイッチ・リマインドのタイミング・基準時刻はいずれも決められた選択肢からの選択のみを受け付けるため、入力チェックは無い。

## 5. 操作と遷移先

| 操作 | 動作 | 遷移先 |
| --- | --- | --- |
| 表示名の「保存」 | `PATCH /users/me` を呼ぶ。成功したらトーストで `表示名を変更しました。` を表示する | 同画面 |
| 通知のスイッチを切り替える | `PATCH /notification-settings/:type` を呼ぶ。成功してもトーストは出さず、スイッチの状態で結果を示す | 同画面 |
| リマインドのタイミングを変える | `PATCH /notification-settings/due_soon` を呼ぶ。成功したらトーストで `リマインドのタイミングを変更しました。` を表示する | 同画面 |
| 基準時刻を変える | `PATCH /users/me` を呼ぶ。成功したらトーストで `基準時刻を変更しました。` を表示する | 同画面 |
| 「通知を許可する」 | ブラウザの許可リクエストを表示する。許可されたら購読情報を `POST /push-subscriptions` で登録し、トーストで `この端末で通知を受け取れるようになりました。` を表示する | 同画面 |
| 「ログアウト」 | 確認ダイアログ（`AlertDialog`）で `ログアウトします。よろしいですか？` を表示する。承諾したら `POST /auth/logout` を呼ぶ | ログイン画面 |
| 戻る | | ToDo一覧画面（グループ未所属なら家族グループ作成・参加画面） |

- スイッチは押した時点で先に見た目を切り替え、失敗した場合は元に戻してエラー文言を表示する。

## 6. 権限による差

無い。すべての項目が自分自身の設定であり、他のメンバーの設定を見ることも変えることもできない。

## 7. エラー時の表示文言

| 状況 | 表示文言 | 表示場所 |
| --- | --- | --- |
| 表示名が未入力・文字数超過（`400`） | 「4. 入力チェック」の文言 | 表示名の入力欄の下 |
| 表示名の保存に失敗（`500` 系） | `表示名の保存に失敗しました。もう一度お試しください。` | トースト |
| 通知設定の保存に失敗 | `通知設定の保存に失敗しました。もう一度お試しください。` | トースト（スイッチを元の状態に戻す） |
| 基準時刻の保存に失敗 | `基準時刻の保存に失敗しました。もう一度お試しください。` | トースト |
| ブラウザで通知を拒否された | `通知が許可されませんでした。ブラウザの設定から許可できます。` | トースト |
| 購読情報の登録に失敗 | `通知の設定に失敗しました。もう一度お試しください。` | トースト |
| 未認証（`401`） | `ログインの有効期限が切れました。もう一度ログインしてください。` | トースト（表示後、ログイン画面へ移動する） |
| 通信できない | `通信に失敗しました。電波状況を確認してもう一度お試しください。` | トースト |

## 8. DBへの影響

| 操作 | 影響 |
| --- | --- |
| 表示名の保存 | `users` の該当行の `display_name` を更新する |
| 基準時刻の変更 | `users` の該当行の `default_due_time` を更新する（時刻だけを持つ項目。既定値は `20:00`） |
| 通知のON/OFFの切り替え | `notification_settings` の該当行（`user_id` と `notification_type` で特定）の `enabled` を更新する |
| リマインドのタイミングの変更 | `notification_settings` の `notification_type = due_soon` の行の `remind_before_value`・`remind_before_unit` を更新する |
| 通知の許可 | `push_subscriptions` に1件追加する（同じ `endpoint` が既にあれば追加しない） |
| ログアウト | DBの更新は行わない。ログインセッションを破棄するのみ（`push_subscriptions` は残す。同じ端末で再ログインしたときにそのまま通知を受け取れるようにするため） |

## 9. 使用API

| API | 用途 |
| --- | --- |
| `GET /users/me` | 表示名・メールアドレス・基準時刻の取得 |
| `PATCH /users/me` | 表示名・基準時刻の変更 |
| `GET /notification-settings` | 通知種別ごとのON/OFF・リマインドのタイミングの取得 |
| `PATCH /notification-settings/:type` | 通知設定の更新 |
| `POST /push-subscriptions` | Push通知の購読情報の登録 |
| `POST /auth/logout` | ログアウト |
