# 家族 de TODO！ 要件定義書

## 1. システム概要

家族間で日常のちょっとしたToDo（買い物・ゴミ出し・提出物確認・予約など）を共有・管理するスマートフォン向けPWA。Frontend（Next.js）とBackend（Express + REST API）を分離し、Cloudflare D1にデータを保存する。認証はGoogleログイン、通知はWeb Push。

## 2. 背景・目的

- 家族内で継続して実際に使えるToDo共有アプリを作る。
- 同時に、TypeScript / Next.js / Express / REST API / Cloudflare / Cloudflare D1 / Googleログイン / PWA / Web Push / GitHub Actions によるCI/CDなど、実務に応用できる技術・開発プロセスを習得する。
- 将来的に会社の業務システム開発にも応用できる構成・開発プロセスを意識する。

## 3. 想定利用者

- 1つの家族グループに属する大人のメンバー（数名程度）。全員がGoogleアカウントを持つ。
- 未成年（子供）は、当面は自分自身でログインする利用者としては想定しない（「12. データ要件」の非登録メンバーとして担当者にのみ設定できる）。

## 4. 利用シーン

- 外出先や自宅で、思いついたToDoをスマートフォンから素早く追加する。
- 家族の誰かが担当者になっているToDoの進捗・期限を確認する。
- 期限が近づいた・過ぎたToDoについて、Push通知で気づく。
- 完了したToDoにチェックを入れ、家族に完了を共有する。

## 5. システム境界

```
[Next.js (PWA, Frontend)]
        │ REST API (HTTPS)
        ▼
[Express (Backend)]
        │
        ▼
[Cloudflare D1 (Database)]
```

- 認証: Googleログイン（OAuth）。
- 通知: Web Push（VAPID）。期限チェック等の定期処理はCloudflare Cron Triggers系の仕組みを候補とする。
- 対象外: アプリストア配信、他の外部サービス（カレンダー等）との連携（将来拡張）。

## 6. 機能一覧

- 家族グループの作成・招待・参加・退出・削除
- Googleログイン
- ToDoの作成・編集・削除・完了/未完了切り替え
- ToDoの担当者設定（複数人・非登録メンバー対応）
- ToDoの繰り返し設定
- ToDoへのコメント
- カテゴリによる分類
- Push通知（追加・担当者設定・期限接近・期限超過）
- 通知の種類ごとのON/OFF設定
- 個人設定（表示名、リマインド時間）
- iOS向けインストール案内

## 7. 機能要件

### 7.1 家族グループ・ユーザー

- 1ユーザーは常に1つの家族グループにのみ所属する（MVP。複数グループ対応は将来拡張）。
- 家族グループへの参加は、招待リンク／招待コードの共有によって行う。
- 招待リンクの発行は、グループの全メンバーが行える。
- グループ内の権限は全メンバーで同一とする（管理者／一般メンバーの区別はMVPでは設けない）。
- メンバーは自分の意思で家族グループから退出できる。
- 家族グループそのものを削除（解散）する機能を設ける。実行できるのはグループの作成者のみとする（他の操作はメンバー全員同一権限だが、グループ削除に限り例外とする）。削除前に確認ダイアログを表示する。
- メンバーの表示名は、Googleアカウントの氏名とは別に、アプリ内で個別に設定できる。

### 7.2 ToDo

- 入力項目: タイトル（必須）、詳細メモ（任意）。
- 担当者: 0人以上、複数人を設定できる。
- 担当者には、アプリにログインしていない非登録メンバー（名前のみ登録、例: 子供）も設定できる。ただし非登録メンバーを担当者に含める場合は、通知を受け取る「フォロー役」として登録メンバーを最低1人あわせて担当者に追加する。当該ToDoに関する通知はフォロー役に届く。
- 期限: 任意設定。日付のみ、または日付＋時刻を指定できる。
- 優先度: 「高・中・低」の3段階を設定できる。一覧・詳細では色分けバッジで表示する。
- カテゴリ: 「学校・仕事・習い事・家事・買い物・その他」の固定6種類から選択する（MVPでは編集不可。編集機能は将来拡張）。
- 作成者・完了者を各ToDoに表示する。担当者・期限以外の変更履歴（誰がいつ何を変更したか）はMVPでは記録しない。
- 完了状態は「完了」「未完了」のタブで切り替えて表示する。完了済みToDoは未完了に戻せる（取り消し可能）。
- 完了・不要になったToDoは、ユーザーが手動で物理削除できる。
- 繰り返し設定を持つToDoを作成できる。対応パターンは「毎日」「毎週（曜日指定）」「毎月（日付指定）」の3種類とする。
- 各ToDoにコメントを残せる（家族間のメモ・やりとり用）。投稿者本人に限らず、家族グループの全メンバーが任意のコメントを編集・削除できる。既読管理は行わない。
- 担当者として設定する非登録メンバー（名前のみのメンバー）は、家族グループ設定画面で事前登録した共有リストから選ぶ。同一グループ内で同名の非登録メンバーは登録できない（グループ内で名前が一意）。

### 7.3 通知（Web Push）

MVPで実装する通知は以下の4種類。

| 通知 | 送信対象 | タイミング |
| --- | --- | --- |
| ToDo追加 | 登録者本人を含む家族グループ全員 | ToDo作成時 |
| 担当者設定 | 担当者に設定された本人（非登録メンバーの場合はフォロー役） | 担当者設定時 |
| 期限接近（リマインド） | 担当者（非登録メンバーの場合はフォロー役） | 期限の何時間・何日前に送るかはユーザーが選択（例: 1時間前・1日前） |
| 期限超過 | 担当者（非登録メンバーの場合はフォロー役） | 期限を過ぎても未完了の場合 |

- 通知のON/OFFは、通知の種類ごとにユーザー単位で設定できる。
- Push通知の許可リクエストは、初回ログイン直後にブラウザへ表示する。

### 7.4 PWA・UI

- スマートフォンでの利用を第一に設計する。PCブラウザからも利用できるが、PC専用のレイアウト最適化はMVPでは行わない。
- ホーム画面に追加（インストール）しなくても、通常のブラウザ上のWebアプリとして全機能を利用できる。
- オフライン対応（電波なし環境での閲覧・操作）はMVPでは不要。常にオンライン接続を前提とする。
- iOSではPush通知の受信にホーム画面への追加（インストール）が必須という制約がある（「16. 技術的制約」参照）。未インストールのiOSユーザーには、インストールを促す案内を表示する。

## 8. 非機能要件

- 個人（家族）利用を前提とした小規模なアプリとして構築する。大規模な監視体制・可用性SLA・バックアップ運用は想定しない。
- Cloudflareの無料枠の範囲内での運用を基本方針とする。無料枠を超える可能性があるサービスを採用する場合は、事前に説明・相談する。
- 想定同時利用者数は家族の人数程度（数名〜十数名規模）。

## 9. 認証・権限

- 認証はGoogleアカウントによるログインのみ。アプリ独自のパスワードは持たない。特定のGoogleアカウント・ドメインへの制限は設けない。家族グループへの参加自体は招待リンク／招待コードの共有によって制御する（「7.1 家族グループ・ユーザー」参照）。
- 権限は「7.1 家族グループ・ユーザー」のとおり、グループ内で一律（管理者／一般の区別なし。ただし家族グループ削除は作成者のみの例外）。
- 未成年者自身のログインはMVPでは想定しない。

## 12. データ要件

- 家族グループ、ユーザー（Googleアカウント連携）、非登録メンバー（名前のみ）、ToDo、担当者（ユーザー／非登録メンバーの中間データ）、コメント、カテゴリ（固定マスタ）、通知設定を管理する。
- 具体的なテーブル定義・カラム設計は基本設計（`docs/specs/02_basic-design/`）で行う。
- 削除は物理削除を基本とする（ToDoの削除、グループの削除）。

## 15. 将来拡張

- 1ユーザーが複数の家族グループに所属できるようにする。
- グループ内の権限を差別化する（管理者／一般メンバー）。

## 16. 技術的制約

- **Cloudflare D1はCloudflare Workersのバインディング経由での利用が基本**であり、Workers外の通常のNode.jsプロセスから直接TCP接続することはできない。Backend（Express）の実行基盤は、**Cloudflare Workers上でExpressを動かす方式を第一候補**とする。Node.js標準API互換性等の技術的な実行可否・詳細構成は基本設計で確定する（実行不可と判明した場合はPages Functions等の別構成を検討する）。
- **Express（Node.js前提のフレームワーク）をCloudflare Workersのランタイムで動かす場合、Node.js標準APIへの依存度によっては互換性の確認が必要**。基本設計フェーズで実行可否・制約を整理する。
- **iOS SafariのPWAは、Web Push通知の受信にホーム画面への追加（インストール）が必須**（iOS 16.4以降）。ブラウザタブのままではPush通知を受け取れない。
- Web Push（VAPID）の実装は一般にNode.jsの`crypto`に依存するライブラリを使うことが多く、Cloudflare Workers環境での互換性を基本設計で確認する。
