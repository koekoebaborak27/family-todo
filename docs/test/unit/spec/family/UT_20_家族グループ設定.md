# 単体テスト仕様書: 家族グループ設定

## 1. テスト対象

- 対象機能: 家族グループ設定
- 対象画面またはAPI: 家族グループ設定画面（`/family/settings`）
- 対象ファイル: `apps/frontend/src/modules/family/ui/family-settings-screen.tsx`、`apps/frontend/src/modules/family/api-client.ts`、`apps/frontend/src/modules/family/service.ts`、`apps/backend/src/modules/family/service.ts`、`apps/backend/src/modules/family/routes.ts`、`apps/backend/src/modules/family/validation.ts`
- 関連DBテーブル: `families`、`users`、`unregistered_members`、`todos`、`todo_assignees`、`sessions`
- 関連設計書: [`20_家族グループ設定.md`](../../../../specs/02_basic-design/family-todo/20_家族グループ設定.md)（本テスト仕様書作成にあわせて、設計書と実装の食い違い3点を解消・記載している。詳細は「7. 補足」参照）

## 2. 前提条件

- 実行環境: ローカル（`pnpm dev:backend` = http://localhost:8787 / `pnpm dev:frontend` = http://localhost:3000）
- ログインユーザー: 実際のGoogleアカウントは使用せず、[`ローカルD1へのセッション投入によるUI確認.md`](../../../../todo/notes/ローカルD1へのセッション投入によるUI確認.md)の手順でログイン済み状態を再現する
- 権限: 「6. 権限による差」のとおり、グループの削除のみ作成者限定。それ以外は全メンバー一律
- 事前DB状態（共通シード。以下の記号を各テストケースの「前提条件」列で参照する）:
  - `F1`: `families`に1件（`name = 'テスト家族'`、作成者`U1`）
  - `U1`: `users`に1件、`family_id = F1`、有効な`sessions`を持つ（ログイン中のユーザー本人。表示名「テスト太郎」。`F1`の作成者）
  - `U2`: `users`に1件、`family_id = F1`（表示名「花子」）
  - `M1`: `unregistered_members`に1件、`family_id = F1`、`name = 'じいじ'`。非登録メンバー0件の確認をするケースでは投入しない
  - 使用するテストデータ: 上記`F1`/`U1`/`U2`/`M1`。グループ退出・削除系のテストケースは、他のケースへ影響しないよう専用の家族グループ・ユーザーを個別に用意する

## 3. テスト観点

- 正常系: 初期表示（グループ情報・メンバー・非登録メンバー・招待情報）、非登録メンバーの追加・削除、招待リンクのコピー・招待コードの再発行、グループの退出（他メンバー残存／作成者引き継ぎ／最後の1人）、グループの削除
- 異常系: 画面表示時の未認証（401）・グループ未所属（403）、各操作時の未認証（401）、非登録メンバーの追加・削除失敗、削除対象の非登録メンバーが既に無い（404）、クリップボードコピー失敗、招待コード再発行・退出・削除の失敗
- 境界値: 非登録メンバー名の未入力、20文字ちょうど／21文字、名前の重複（409）
- 権限: グループ削除ボタンは作成者にのみ表示される
- DB更新: 非登録メンバーの追加・削除（`todo_assignees`との連動）、招待コードの再発行、退出時の`users.family_id`・`todo_assignees`・`families.created_by_user_id`の更新、削除時の`families`・`todos`・`todo_assignees`・`comments`・`unregistered_members`の物理削除と`users.family_id`のリセット
- 画面表示: メンバー行の「(あなた)」「(作成者)」表示、非登録メンバー0件のメッセージ、招待コード有効期限切れの表示、退出確認ダイアログの文言分岐（他メンバー残存／自分が最後の1人）

## 7. 補足

- 画面表示時（初回読み込み）の401（未認証）・403（グループ未所属）は、設計書「7. エラー時の表示文言」がトースト表示後の画面遷移を求めているのに対し、実装（`family-settings-screen.tsx`の`loadSettings`）はトーストを出さず即座に画面遷移するのみだった。ToDo一覧・ToDo詳細でも同じパターンが見つかっており、その際と同じ方針（実装どおり）とすることをユーザーに確認し、設計書に注記を追加した（TC-023・TC-024）。
- 作成者以外がグループ削除を実行したとき（`403`）のサーバー側エラー文言は、設計書の文言（`家族グループを削除できるのは、グループを作成した人だけです。`）とサーバー実装の文言（`家族グループを削除できるのは作成者だけです。`）が異なっていた。ユーザー承認のうえサーバー側の文言を設計書に合わせて修正した（`apps/backend/src/modules/family/service.ts`）。ただし画面側は削除ボタン自体が作成者にしか表示されないため、この`403`を専用扱いする分岐を設けていない。通常の画面操作では到達しない経路のため、専用のテストケースは設けていない。
- 各操作（招待コード再発行・退出・グループ削除・非登録メンバーの追加・削除）中の未認証（401）は、設計書がトースト表示後のログイン画面遷移を求めているのに対し、実装は操作別の汎用失敗メッセージを表示するのみでログイン画面へ遷移しない状態だった（ToDo詳細のコメント操作で見つかったのと同じパターン）。ユーザー承認のうえ設計書どおりの挙動になるよう`family-settings-screen.tsx`の各操作ハンドラへ401判定を追加した。TC-032は代表として招待コード再発行時の401を確認する（他の操作も同じ共通処理`handleUnauthorized`を通るため、個別のテストケースは設けていない）。
- 「作成者が退出したときの引き継ぎ先（`users.created_at`が最も早い人）」の具体的な判定順は詳細設計に記載が無く基本設計「8. DBへの影響」の記載のみだが、実装（`findOldestFamilyMemberExcept`）と一致することをコードで確認済みのため、確認は不要と判断した。
