# 単体テスト仕様書: 家族グループ作成・参加

## 1. テスト対象
- 対象機能: 家族グループ作成・参加
- 対象画面またはAPI: 家族グループ作成・参加画面（`/family/setup`）、招待リンク振り分け画面（`/join?code=`）
- 対象ファイル: `apps/frontend/src/modules/family/ui/family-setup-screen.tsx`、`apps/frontend/src/modules/family/ui/join-redirect-screen.tsx`、`apps/frontend/src/modules/family/service.ts`、`apps/frontend/src/modules/family/validation.ts`、`apps/frontend/src/modules/family/api-client.ts`
- 関連DBテーブル: `families`、`users`、`sessions`
- 関連設計書: [`12_家族グループ作成・参加.md`](../../../../specs/02_basic-design/family-todo/12_家族グループ作成・参加.md)（本テスト仕様書作成にあわせて、設計書と実装の食い違い3点のうち本画面に関わる1点＝Push通知許可リクエストの記載を、実装に合わせてテスト対象から除外している。詳細は「7. 補足」参照）

## 2. 前提条件
- 実行環境: ローカル（`pnpm dev:backend` = http://localhost:8787 / `pnpm dev:frontend` = http://localhost:3000）
- ログインユーザー: 実際のGoogleアカウントは使用せず、[`ローカルD1へのセッション投入によるUI確認.md`](../../../../todo/notes/ローカルD1へのセッション投入によるUI確認.md)の手順でログイン済み状態を再現する
- 権限: 無し（設計書「6. 権限による差」のとおり、グループ未所属のユーザーは全員が作成・参加どちらも行える）
- 事前DB状態（共通シード。以下の記号を各テストケースの「前提条件」列で参照する）:
  - `U1`: `users`に1件、`family_id = NULL`（未所属。有効な`sessions`を持つログイン中のユーザー本人）
  - `F1`: `families`に1件（`name = 'テスト家族'`、`invite_code = 'ABCDEF12'`、`invite_code_expires_at`は現在時刻より未来）。参加系のテストケースでのみ投入する
  - `F2`: `families`に1件（`invite_code_expires_at`が現在時刻より過去＝期限切れ）。期限切れケースでのみ投入する
- 使用するテストデータ: 上記`U1`/`F1`/`F2`

## 3. テスト観点
- 正常系: 初期表示、タブ切り替え、グループ作成、招待コード参加、招待リンク（`/join?code=`）からの遷移
- 異常系: セッション失効（401）、既に所属済み（409）、招待コードが正しくない（404）、招待コードの期限切れ（400）、サーバーエラー・通信エラー
- 境界値: グループ名30文字ちょうど／31文字、招待コード8桁ちょうどの前後、招待コード未入力
- 権限: 該当なし（「6. 権限による差」のとおり差が無いため。「7. 補足」に記載し省略する）
- DB更新: グループ作成時の`families`追加・`users.family_id`更新、参加時の`users.family_id`更新（`families`は変更しない）
- 画面表示: タブの既定選択、招待リンク経由での初期タブ・コード欄の事前入力、送信中のボタン操作不可、エラー文言の表示位置

## 7. 補足
- 設計書「5. 操作と遷移先」に「初回ログイン直後にこの画面へ来た場合は、画面表示のタイミングでブラウザのPush通知許可リクエストを表示する。」とあるが、実装（`family-setup-screen.tsx`）には該当処理が無く、Push通知許可リクエストはToDo一覧画面側で行われている。ユーザー承認のうえ、本仕様書ではこの画面でのPush通知許可リクエストのテストケースを設けていない。
- 設計書「7. エラー時の表示文言」にはサーバーエラー（500系）・通信できない場合の文言もあるが、これらはコード上分岐が用意されている一方でローカル環境から意図的に再現するのが難しいため、テストケースとして起こしていない（`ui/family-setup-screen.tsx`の`handleFamilyError`のコード読解で文言自体は確認済み）。
- iOSインストール案内バナー（`<IosInstallBanner />`）の表示条件は別画面（iOSインストール案内）の仕様書側でテストする対象とし、本仕様書では扱わない。
