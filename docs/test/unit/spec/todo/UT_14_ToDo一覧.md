# 単体テスト仕様書: ToDo一覧

## 1. テスト対象
- 対象機能: ToDo一覧
- 対象画面またはAPI: ToDo一覧画面（`/todos`）
- 対象ファイル: `apps/frontend/src/modules/todo/ui/todo-list-screen.tsx`、`apps/frontend/src/modules/todo/service.ts`、`apps/frontend/src/modules/todo/api-client.ts`、`apps/frontend/src/modules/todo/push-subscription.ts`
- 関連DBテーブル: `families`、`users`、`categories`、`todos`、`todo_assignees`、`unregistered_members`、`comments`、`push_subscriptions`、`sessions`
- 関連設計書: [`14_ToDo一覧.md`](../../../../specs/02_basic-design/family-todo/14_ToDo一覧.md)（本テスト仕様書作成にあわせて「7. エラー時の表示文言」の401/403の記載を実装に合わせて修正済み）

## 2. 前提条件
- 実行環境: ローカル（`pnpm dev:backend` = http://localhost:8787 / `pnpm dev:frontend` = http://localhost:3000）
- ログインユーザー: 実際のGoogleアカウントは使用せず、[`ローカルD1へのセッション投入によるUI確認.md`](../../../../todo/notes/ローカルD1へのセッション投入によるUI確認.md)の手順でログイン済み状態を再現する
- 権限: 無し（設計書「6. 権限による差」のとおり、グループメンバーであれば誰のToDoでも同じ操作ができる）
- 事前DB状態（共通シード。以下の記号を各テストケースの「前提条件」列で参照する）:
  - `F1`: `families`に1件（`name = 'テスト家族'`）
  - `U1`: `users`に1件、`family_id = F1`、有効な`sessions`を持つ（ログイン中のユーザー本人。表示名「テスト太郎」）
  - `U2`: `users`に1件、`family_id = F1`（担当者用の別メンバー。表示名「花子」）
  - `M1`: `unregistered_members`に1件、`family_id = F1`、`name = 'じいじ'`（非登録メンバー）
  - `categories`: 固定6件（学校・仕事・習い事・家事・買い物・その他）は既存のseedをそのまま使う
  - `todos`: テストケースごとに必要な件数・状態を追加投入する（各TCの「前提条件」列に明記）
- 使用するテストデータ: 上記`F1`/`U1`/`U2`/`M1`と、各TCで追加する`todos`

## 3. テスト観点
- 正常系: 初期表示、完了状態タブ、並び順タブ・プルダウン、カテゴリ絞り込み、完了/未完了切り替え、メニュー遷移、ログアウト、再読み込み、カード内の各種表示
- 異常系: セッション失効（401）、グループ未所属（403）、一覧取得のサーバーエラー・通信エラー、完了/未完了切り替え時の対象削除（404）・サーバーエラー
- 境界値: 該当0件（絞り込み無し／カテゴリ絞り込み）、期限が同一のタイブレーク、期限なしの末尾集約
- 権限: 該当なし（「6. 権限による差」のとおり差が無いため。「7. 補足」に記載し省略する）
- DB更新: 完了/未完了の切り替え、ログアウトによるセッション失効、Push通知購読の登録
- 画面表示: タブ・プルダウン・チップの切り替え表示、カードの表示制御（期限超過・繰り返し・担当者・コメント件数）、0件時のメッセージ

## 7. 補足
- 「権限」の観点は対象外（設計書「6. 権限による差」のとおり、グループメンバー間で操作・表示の差が無いため）。
- TC-031〜TC-033の401/403時の挙動は、当初の設計書「7. エラー時の表示文言」に「トースト表示後に画面遷移」とあったが、実装（`todo-list-screen.tsx`）はトーストを出さず即座に画面遷移する。ユーザー承認のうえ、設計書側を実装にあわせて修正済み（本仕様書は修正後の設計書に準じる）。
- TC-034〜TC-037（サーバーエラー・通信エラー・対象削除）は、DB操作だけでは再現できない状況（500・通信断）を含むため、Playwrightの API モック（`page.route`等）を用いる想定。TC-036は対象ToDoの事前削除でも再現できるため、DB操作を優先してよい。
- TC-038・TC-039はブラウザのPush通知許可ダイアログを伴うため、PlaywrightのChromium権限付与（`context.grantPermissions`等）を用いる想定。
